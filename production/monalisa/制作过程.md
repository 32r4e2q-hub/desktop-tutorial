# 制作过程 · 蒙娜丽莎：行李箱里的779号

> 与《吉尔戈海滩：纸箱里的名单》同一条流水线（`production/gilgo/`），画风、卡片、口播节奏全部对齐。
> 这份日志记的是**这一部**特有的判断与踩坑，通用流程看根目录 `新题目开工手册.md`。

## 一、题目与事实边界（最先定，决定后面所有事）

委托方给的题面里有一句「用微观画布纤维比对破案」。查完能找到的史料（维基、Smithsonian、BBC、
ThoughtCo、NOISE、吉尼斯、界面、澎湃）之后，**没有任何一条来源支持"白杨木纤维"这个说法**——
它是中文自媒体在转述时加上去的戏剧化细节。

处理方式（也是本片最重要的一条判断）：不把假细节当证据用，而是**把它写进片子里当成"流传版本"并且当场拆掉**：

- N06 开头两镜（S39-S40）先把传说摆出来；
- S38 信息卡「流传与档案」左右两栏对照：传说=一根纤维 vs 档案=馆藏编号 INV 779；
- 真正有来源的证据链承担高潮：贝尔蒂永在画框上取到的那枚**左手拇指**指纹（警方当年只存了右手，
  跟两百多名馆员逐一比对全部对不上，而佩鲁贾恰好是没来按手印的那一个），
  以及 1913-12-10 在佛罗伦萨旅馆房间里对着窗光翻到画板背面看到的**卢浮宫馆藏编号 779**（乌菲兹馆长 Poggi 验画）。

每条解说句都能在 `story.json.sources`（12 条）里找到落点；这是本仓库的硬规则。

## 二、结构

六章 45 镜，30 秒一格（`GRID=4` → 45×4=180s）。963 字口播。
信息卡 7 张卡在 S05 / S11 / S17 / S25 / S33 / S38 / S44，全部落在"数字出现的那一句"上。
运镜 26 种（参考片 19 种，不回退成单一飞入）。

## 三、配音与切点（本轮最容易做错的地方）

1. 音色：Arena 试听后选定 `voice-00`（与《黑色大丽花》《吉尔戈海滩》同一把嗓子，频道一致性）；
   六段原始录音在 `audio/raw/`，`tighten_pauses.py` 只剪过长静音、逐字不动：185.42s → **179.12s**，
   渲染变速 **1.066×**（闸门 0.86–1.10）。文本不需要再删。
2. `clause_times.py` 逐字戳点 → `audio/clause-times.json`，`--check-cuts` 用来证明每个切点都落在停顿窗里。
3. **切点必须按"成片时间"算，不是按配音原始时间算。** 第一版按 raw 时间给了 2.05s 下限，
   结果 render 出来 S18=1.97s、S45=10.73s（要 1.52× 慢放，直接撞 1.33× 闸门）。
   原因是 raw 时间还要除以 1.066 的变速，章末那一镜还要吸收 GAP 与片尾。
   → `make_cuts.py` 改成在 raw 域用 **[2.20, 7.50]** 求解（等价成片 [2.06, 7.04]，
   末镜再加 GAP+OUTRO 也仍在 9.37s 闸门内），`plan_cuts.py` 负责把"每镜到底盖住哪几个分句"打出来给人看。
4. **切法一变，画面就必须跟着重排。** 求解器挪动边界之后，解说会比画面快一拍（这正是参考片被批评过的
   "解说跟画面对不上"）。做法：先 `plan_cuts.py` 枚举全部可行切法，按语义偏移最小排序，
   再把 `build_story.py` 的 SHOTS（叙事职责＋提示词＋运镜）整体搬到新的分句分组上——
   本轮 N01 重排 8 镜、N03 画面轨后挪一拍并新写 S22「裹画特写」、N06 收尾一镜去掉与卡片重复的半句。
   对位表由 `build_story.py --script` 写进 `抖音脚本.md`，时间轴是真实配音时长，不是估算。

## 四、本轮抓到并修掉的工程缺陷

| 症状 | 根因 | 修法 |
|---|---|---|
| 提示词里 `thedoorway`、`insideways` 这类粘连词 | 多行字符串字面量拼接时行尾漏了空格，Python 直接首尾相接 | 只在"英文提示词字段"内按 `,` 边界补空格，共 **197 处**；`build_story.py` 末尾加了粘连词自检（>17 字母的纯词） |
| `build_audio.py` 崩：`write_sfx() missing 'presentation'` | render.write_sfx 加了 presentation 参数，独立脚本没跟着改 | 传 `project.get('presentation') or {}` |
| DP 求解器 `TypeError: list indices must be integers` | 回溯时踩到 INF 状态（末段没有满足最小时长的候选） | 末段单独过滤 `duration - start >= MIN_SLOT`，并显式报错"该章需要改镜头数或改解说" |
| 联络表扫描把夜景镜头误判成"画幅不对" | 用第一格亮度求内容区，暗场必然算出窄条 | 黑边改成"所有格取交集"；画幅/帧率优先读 `qa/Sxx.json` 的 probe 元数据 |

## 五、素材还没到位时先把闸门二跑通

Agnes 只能在有 API 出口的地方生成，但 render 的硬闸门跟内容无关。
`slate_render.py` 生成 38 块会动的场记板当替身（1920×1080/24fps/7.04s/h264+aac），
按 `generate.request_hash` 造一份**标注为测试夹具**的 `results.json`（放 `work/`，不入库），
本地跑完整 render：

```
RENDER_COMPLETE 180.0s 1920x1080 30fps frames=5400 · −20.57 dBFS · peak −1.66 · silence 1.1% · tempo 1.0662
```

`production/review_film.py` 对替身片同样跑通（黑帧/静止段/逐章响度/语速）；替身片报的
"13 帧接近全黑、50 处真静止"是场记板自己的性质，不是片子的问题。
**交付片仍必须由 render 工作流用真 Agnes 素材重跑一次**——render.py 里那句
`refusing to substitute an image/slideshow` 就是为这件事留的门。

## 六、逐格 QA 扫描

`scan_qa.py` 把 `qa/Sxx.jpg`（2fps×16 格）自动过一遍，抓五类：中途换场尖峰、黑格/过曝、
画幅与帧率（读 probe）、整段冻住、构图尺度漂移（越拍越近）。
在参考片上校准：38 张表 0 fail / 6 warn，warn 全是"Agnes 自己把近景推近"这一类，
说明阈值可用、也说明这一类缺陷在上一部里确实存在。

## 七、还差什么（按顺序）

1. Agnes 生成：`GEN_REQUEST` 已推（`{"workers":2}`），等 GitHub Actions 的 job 被 runner 领走。
   本仓库的 job 走 `vars.RUNNER_LABEL`；那台机器不在线时 job 只会排队，沙箱这边看不见队列。
2. 逐格 QC → 不合格镜头用 `{"workers":1,"only":"Sxx"}` 重做（最多两轮）。
3. `RENDER_REQUEST` → 真素材成片 → `review_film.py` + `scan_qa.py` + 抽帧看字幕。
4. `VERBATIM_REQUEST`（ASR 逐字校对，字幕与口播必须 100% 一致）。
5. `RELEASE_UPLOAD_REQUEST` → Release 挂 `蒙娜丽莎_行李箱里的779号_三分钟_带声音.mp4`。
6. `抖音发布文案.md` 已生成（三个标题 + 简介 + 置顶提问 + 话题），发布前照例人工过一遍违禁词。
