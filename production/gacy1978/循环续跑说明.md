# 智谱免费生成循环续跑

本次依据仓库 `production/kitakyushu2002/auto_resume.py` 的容量退出码/轮次预算机制，以及已有工作流的 `gh workflow run --ref` 官方派发方法实现；没有恢复旧 `production/gacy` 实验接力。

## 原失败原因与修正

旧运行40069121240已生成6段，S08遇到429/1305，20次提交重试耗尽后抛异常终止，工作流没有后续接力。

现在：

1. SDK关闭隐藏重试，单请求60秒超时；容量错误按30、60、120、240、最多300秒加少量抖动退避，不密集请求。
2. 每次拥堵立刻写 `results.json`：错误、重试次数、等待时间；不再长期只显示submitting。
3. 单轮默认25分钟，轮询中的已受理任务到时保留task_id；下一轮先查同一任务，**不因为单轮结束重投已知任务**。
4. 已完成镜头按同一请求哈希、视频URL和SHA复用；已有6段不重做。请求哈希没有改变。
5. 容量/暂时网络问题或仍在排队以42退出；工作流先持久化全部收据，再冷却120秒，用GITHUB_TOKEN的actions:write正式派发同一工作流下一轮。串行concurrency，不会自我取消。
6. 新的 `loop_control.py` 只认容量/待完成任务的42；1301、认证、余额、参数错误或程序错误不接力，保留诊断等待修正，不绕过审核。
7. **38条当前请求收据全部完成，且都有64位SHA、正字节数和解码成功记录**，才自动派发初剪渲染。渲染成功后自动派发逐字听检和全帧/角色脸复核。
8. 机器检查仍只是技术/视觉分诊；初剪不会自动冒充“同脸与人工语义已签收”的终版。

## 安全上限与停止

- 最多40轮，每轮25分钟；不是无限空烧runner。达到预算会明确失败并留下原因，需人工确认继续。
- 创建 `production/gacy1978/LOOP_STOP` 并推送可以停止后续生成和接力；也可以直接在Actions取消当前运行。
- 手动 `only` / `force` 请求不会自动串成全量循环；普通自动请求不携带force。
- 控制记录在 `loop-state.json`；其中dispatch是意图，是否真的派发以该运行最后一步及下一条Actions记录为准。Git持久化失败或官方派发失败会使工作流报错，不掩盖为已接力。
- 全程只允许 `cogvideox-flash`，不读取/打印API密钥，不切换付费模型。

## 最新用户修订：线性短间隔（覆盖上面的指数退避与120秒冷却描述）

- 第一次提交遇到暂时拥堵后等20秒，第二次等25秒，第三次等30秒，此后每次加5秒。
- 去掉随机抖动与额外120秒接力等待；每轮最多20次提交，下一轮重新从20秒递增。单轮预算、40轮保护及认证/审核停止条件不变。
- 如果服务器明确返回更长的Retry-After，遵守该返回值；不绕过服务端限流。
- 本次通过专属restart工作流进入同一concurrency组，先取消旧节奏的运行，再官方派发使用新代码的续跑；不修改已完成片段或请求哈希。
