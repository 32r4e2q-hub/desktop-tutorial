# 制作过程 ·《塔玛姆·舒德：索马顿海滩无名男尸》

> 三分钟横版（16:9 · 1920×1080 · 30fps · 180秒）中文悬疑解说短片。
> 29 个 **Agnes Video 2.5 Flash 连续运动片段**（720P源片后期放大至1080P）+ 原创程序合成配乐/音效。
> 本文件按《新题目开工手册.md》狂犬病模式记录**实际做了什么、遇到什么、怎么解决的**，换题目时可照着走。

---

## 1. 这一部是什么

| 项 | 值 |
|---|---|
| 主题 | 索马顿海滩无名男尸 / 塔玛姆·舒德案（1948-2022） |
| 输入 | 事实核查清单 + `build_story.py` 唯一内容源 |
| 目标 | 180秒 · 29镜 · 9章 · 中文旁白一镜一句 |
| 风格 | 1940年代黑色电影 + 35mm胶片质感，深琥珀/深青对比，审慎调查氛围 |
| 分支 | `arena/dc7c8423-desktop-tutorial` |

与狂犬病模式的差异：
- **29镜而非45镜**：每镜4–9秒，9章与29镜非均匀对应（N01 2镜10秒 … N09 2镜8秒）；
- **一镜一句旁白**：29条独立TTS，每镜一条配音+一条字幕，不跨镜；
- **加速不降速**：保留自然语速，必要时仅加速至1.55倍，禁止慢放填镜。

## 2. 事实核对（先写边界，再写画面）

写在 `build_story.py` / `story.json` / `screenplay.md` 的 `SOURCES` 与 `principles`：

- 每一句解说指向公开来源（南澳档案馆、中澳ABC 2018/2022/2026、Abbott验尸庭转录）；
- **Webb身份**：仅称“研究团队主张”，不称警方确认；注明DNA取自**石膏死亡面模头发**，非遗体；
- **死因/密码/护士**：均标为“未定论/无公认解读”，不包装成事实；
- **画面护栏**：逝者仅坐姿剪影/背影/半阴影，不露脸、不特写、不血腥；“间谍/情杀/毒杀”仅作传闻剪影；
- 中文姓名、日期、`Tamam Shud`字样一律后期叠加，不让视频模型拼写。

> 复核时间点：2026-10-22查到最新直接警方状态仍是ABC 2026-07-06“调查仍在进行”，成片按此限定表述。

## 3. 内容源：29镜的唯一真源

`build_story.py` 生成三处逐字一致：
`story.json` / `screenplay.md` / `audio/manifest.json` + `抖音脚本.md` / `抖音发布文案.md`。

| 块 | 内容 |
|---|---|
| `STYLE_PREFIX` / `NEGATIVE_PROMPT` | 3D写实黑色电影调，光束/海雾/颗粒；负面禁可读文字、血腥、现代物 |
| `CHARACTERS` 9种 | 索马顿男子/警察/验尸官/路人/车站职员/护士/现代研究者/传闻剪影/虚构工程师 |
| `SHOTS` 29元组 | id/start/duration/camera/characters/prompt/purpose/seed/seconds/aspect |
| `CHAPTERS` 9章 | 每章含起止、含哪些镜、合并文本；由29镜推导而来 |
| `NARRATION_LINES` 29条 | 每镜一句，例 S14“纸上印着两个波斯语词：‘Tamam Shud’…” |
| `narration_spec` | `voice_id=voice-01, max_speedup_factor=1.55, slowdown_allowed=false, alignment=one-independently-generated-voice-clip-and-one-caption-cue-per-shot` |

## 4. 配音：29句独立TTS + 限速

### 4.1 为什么是一镜一句

旧版按章配音（9段）需把长句慢放拉伸至镜长，听感拖沓。用户反馈“解说太慢要睡着、且易与画面错位”，遂改为**一镜一段TTS**，字幕与声音同起止，画面与口播咬死。

### 4.2 音色与批次

- `voice-01`：用户试听选定的普通话男声（沉稳叙述，有精神）。
- `add_voice` → `generate_speech` 分三批生成：
  - S01–S10（`75bc49c0…` … `c0bd6f41…`）
  - S11–S20（`2919ebe1…` … `b48b21c6…`）
  - S21–S29（`115f594c…` … `0f8cdaf8…`）
- 限制：每会话TTS并发**≤10条**，超限报 `limit 10`；本片分3次完成，共29/29。
- 产物：`production/somerton/audio/S01.mp3 … S29.mp3` + `manifest.json`（含每条`voice_id/target_start/target_duration/alignment/sha256`），本地用 `mutagen` 验长、与 `story.json` 逐字比对。

### 4.3 限速与对时

`build_audio.py`：

- 去除首尾静音 → 量活动时长 → `voice_tempo_factor(max_speedup=1.55)` 仅加速；
- 最长需 `S02 7.368s / 可用4.92s ≈ 1.498×`（实测最大值），1.55可覆盖；
- 每镜字幕=该镜口播文本，时间=声音活动区间，白色黑边底部安全区，关键词金色高亮；
- 原创程序合成BGM/SFX（大提琴/弦乐/海浪/钟声/蒸汽等）在人声下自动压至约−18dB，最后响度/峰值闸门。

变更记录：`1.18 → 1.55`（`af4fa12`），同步改 `build_story.py / build_audio.py / qc.py / manifest.json / screenplay.md / tests`，阈值 `4.8s → 6.4s`。

## 5. 生成：Agnes Video 2.5 Flash

模型：`agnes-video-2.5-flash`，`720P / 16:9 / mode=text / n=1`，负面约束嵌入提示词正文（不发独立negative_prompt）。

- 节流：`throttle.py` 60–61秒共享闸门，临时5xx/429无限重试，尊重Retry-After；
- 收据：`results.json` 记 `task_id/video_url/sha256/reported_size/seconds/decoded_ok/contact_sheet`，按SHA-256断点续跑；
- 工作流：`somerton-gen.yml` 监听分支push，S01 canary成功后连跑全量，超时自动 `workflow_dispatch` 续跑。

关键运行（`arena/dc7c8423-desktop-tutorial`）：

| Run | 工作流 | 结果 | 备注 |
|---|---|---|---|
| 40311434040 | 全量生成 | success | `somerton-3min-agnes-21` 86,137,869B 旧旁白 |
| 40336503467 | 离线自检 | failure | runner硬编码 `ubuntu-latest` 被测试拦 |
| 40336503732 | voiceover v1 | failure | 1.18限速不够（S02需1.498×）|
| 40336823864 | 离线自检 | success | 改 `vars.RUNNER_LABEL \|\| ubuntu-latest` 修好 |

| **40337362149** | 全量生成 | success 9m18s | `somerton-3min-agnes-23` 160,683,882B（同版重渲染）|

教训：

1. **Runner标签别写死**：测试 `test_no_workflow_hardcodes_a_github_hosted_runner` 会拦；改 `vars.RUNNER_LABEL`。
2. **限速要量出来**：先用 `mutagen` 量每条TTS实长 / (镜长−0.08s) 取最大加速比，再定上限。
3. **日志下载不到**：用 `gh run view <id> --json jobs` 看步骤；诊断由工作流commit回分支。

## 8. 本片对SOP的三处补充（换题目注意）

1. **一镜一句 + 1.55限速**：段落式旁白易拖沓；29镜独立TTS+仅加速更利落。超过1.55的镜要改写文案（缩短），不要放宽限速。
2. **TTS ≤10/次**：29镜分批生成，记录每批SHA-256；中途失败重跑该批即可。
3. **发布工作流的target**：用 `$GITHUB_SHA` 而非写死commit；并处理“已存在release”的幂等上传。

## 9. 踩坑清单增补

| 坑 | 结论 |
|---|---|
| 按章配音+按章字幕导致音画错位与慢放 | 改一镜一句，字幕=配音活动区间，限速1.55，不慢放 |
| 限速定1.18不够覆盖S02的1.498 | 先量后定，上限与测试阈值联动改 |
| Runner写死ubuntu-latest | 走 `vars.RUNNER_LABEL \|\| ubuntu-latest`，过 `test_no_workflow_hardcodes` |
| `gh run download` 在沙箱EOF | 沙箱不直下，靠Runner拉artifact再发布 |
| 发布工作流target写死旧commit | 用 `$GITHUB_SHA`，支持已存在tag的幂等 |
