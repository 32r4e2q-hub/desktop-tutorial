## 2. 与上传稿的差异（用户稿 → 成片稿）

1. **40 镜 → 45 镜**：模板的规划网格是 45 镜 × 4 秒（38 动态 + 7 信息卡），
   用户稿的场景全部保留并重排进这个网格，新增的 5 镜用于补足「信息卡 + 过渡」（卡不算动态镜）。
2. **加钩子、加冲突，去掉提前泄底**：用户稿前 8 镜把「火灾 → 失踪 → 逮捕 → 鉴定」一次抖完，
   本片把这些镜头延后到各自章节（S06/S07/S08 换成受害者物件、夜路车灯、寻人启事），
   让「一滴血」留到第四章，与「他提前烧车、格式化硬盘」正面相撞。
3. **人物加厚**：受害者不再是数字——S06 一排随身物件、S17 她的办公桌、S19 歌厅服务员与上班族、
   S20 买完菜的主妇、S21 等车的女大学生、S22 派出所七张失踪表（没有并案）；凶手只给
   「平静、普通、不动声色」的虚构匿名替身（C1），不给「天才罪犯」叙事。
4. **口径冲突按多源一致的写法**（见 史实核对.md 第二节）：逮捕日、被害者年龄、死刑确定日、
   供述节奏、受害人数，都不挑一个说法当结论。
5. **纠正与保留**：用户稿的「取款机假发与避孕套手指」「第六天开口」「袖口 DNA」「牛棚镐头」
   都在公开来源里核实通过，保留；「杀人后微笑的面具」这类描述法未被写成结论，改为
   「表情平静、不动声色」这种可核实的表达。

## 4. 露脸模式（本片重点）

* 5 个角色都是**虚构匿名人物**，不是任何真实人物的容貌还原；片内标签与片尾卡写明「非本人容貌」。
* 面容 token 只在 `cast.json` 里写一份，`build_story.py` 用 `{C1}`…`{C5}` 占位符注入，
  保证同一角色跨镜头逐字节一致；每个角色另有稳定的 seed 记录（SEED_BASE = 20051030）。
* 定妆照（`cast/*.png`）由图像模型生成、逐张人工过目：挑了「背景无可读文字」的版本
  （首批 C1/C2 的背景里出现带字的纸与公告板，已重做）。
* **定妆照探测的结果随服务端负载来回摆，不是一句「支持/不支持」**：第 1、2 轮撞限流
  （1305「该模型当前访问量过大」）→ 02:00 探测收据 `delivery/ref-image-probe.json` 记
  `supported: false`；03:00 再探，同一张图同一段提示词被收下（`supported: true`），
  S04 真的拿到一版**带定妆照的成品**；接着 S05 起带图任务开始排队，20 分钟轮询窗耗尽、
  三次重投全 `polling timeout` —— 一条带图收据能磨掉一小时。
* 因此本片的做法是**两条腿都在**：关键路径（38 镜齐活、能出片）先走纯文生，收据哈希与
  「纯文生」payload 逐镜比对一致、可复核；带图版留到低峰用
  `{"only":"S04,S05,S12,S14,S39","ref_image":true}` 单独补。跨镜头脸的一致性主要靠
  **提示词里的面容 token**，最终由 `face_cast.py check-frames` 画面闸门 + 人眼接触表复核；
  脸漂了的镜头用 `{"only":"Sxx"}` 重做。
* 出片链两侧（`render.py` / `fetch_sources.py`）都认**两种哈希**（纯文生 / 带定妆照，
  `wanted_hashes`），所以这个开关来回切不会把已签收的素材判成缺料。

## 5. 引擎改动（相对模板的增量，都在本目录）

| 文件 | 改动 | 为什么 |
|---|---|---|
| `tools/plan_cuts.py` | 新增：按分句时间 DP 出 `render.py` 的 `CUTS`（每镜 1.8–6.5s，最小化与 4 秒网格的偏差） | 45 镜要落在真实配音的分句停顿里，人工排容易顾此失彼 |
| `clause_times.py` | 新增 `merge_to_fit()`：分句数 > 停顿窗数时合并「TTS 没停顿的地方」 | 本片 N01/N02/N06 的 TTS 有几处一口气念完，K > J+1 时 DP 无解，旧版会退化成 0.00–总长的假数据 |
| `render.py` | `captions_from_clause_times()` 支持「一条字幕吃掉一段的一部分」，段内按字数插值 | 配合上面的合并：字幕显示仍是短句，时间是几百毫秒级近似 |
| `tighten_pauses.py` | 新增 `update_manifest()`：收紧后自动更新 `audio/manifest.json` 的 SHA-256 | 渲染/字幕/听检的输入是收紧后的文件，收据必须记它（手工补容易漏） |
| `generate_cogvideox.py` | ① 探测结果 `delivery/ref-image-probe.json` 随分支提交；② 内容审核拦截（1301）与单镜被拒改成「记 failed、跳过、继续下一镜」；③ 新增**历史收据复用**（`reuse_receipt()`：本轮哈希在 `previous_results` 里找得到就直接恢复，不再重投）；④ 新增 payload 开关 `{"ref_image": false}` 强制纯文生 / `true` 强制带定妆照 | ① 「免费档收不收定妆照」是可复现的关键证据；② 2026-10-12 实测 S22 的 1301 在第 1、2 轮各把整批 38 镜掐断一次——一镜的提示词问题不该让整轮作废；③④ 定妆照开关随限流往返摆动时，同一镜的两种哈希都可能有成品，见第 6 节第 7 条 |
| `tools/smoke_render.sh` | 新增：38 个假镜 + 真实配音把整条 `render.py` 跑通；默认 1920×1080 | 模板的 delogo 固定在水印位置，输出宽度 < 1918 会越界 |

## 6. 踩到与解决的问题

1. **分句对不出时间**（N01/N02/N06）：见上表 `merge_to_fit`。判断依据是音频能量包络本身——
   这几段里 ≥0.18s 的静音只有 12–14 个，而分句有 14–17 个。
2. **本地没有中文字体**：沙箱里没有 `fonts-noto-cjk`，冒烟脚本会从 `mplfonts` 拷同款
   Noto Sans/Serif CJK 到临时 `root/.cache/fonts`（CI 里用 `apt install fonts-noto-cjk`）。
3. **冒烟尺寸**：`delogo=x=1746:w=172` 是给 1920 宽写死的，640×360 的冒烟会在最后一步越界报错，
   脚本默认改成 1920×1080 并在文件头写明。
4. **沙箱推完还要 rebase**：生成侧每完成一镜就 commit+push，我这边推之前必须
   `git pull --rebase`（工作流 push 频繁，直接 push 会被拒）。
5. **工作区配额冲突**：生成侧在分支上跑时，仓库里的 `抖音文案/上传记录.jsonl` 与用户上传稿
   会被工作区快照标记为未跟踪/已修改，先提交它们再 rebase，避免生成侧检查点把它们卷进冲突。
6. **内容审核（1301）有两种到达方式**：一次是轮询接口返回 `task_status=FAIL`，一次是 SDK 直接把
   400 抛成 `APIRequestFailedError` 穿透 `try/except`。第 1 轮死在第一种，第 2 轮死在第二种；
   两次都把整批掐断在 S22（第 19 镜）。修法见第 5 节：两条路径都接住，记 failed 后继续跑。
   另外 S22 的提示词先后去掉「失踪登记表」「照片框」这类元素（画面语义不变，「没有并案的几摞卷宗」），
   第 3 轮验证是否还触发审核；第 4 轮把 S22/S24/S29 三镜整体改成中性场景
   （档案室线托盘 / 夜里普通市政楼 / 单人走过空走廊，去掉警局、警车、制服、押解）。
7. **定妆照开关往返摆动会把已花的成品判成缺料**：第 4 轮开跑时探测是 `supported: true`，
   于是 5 个露脸镜的「带图哈希」与旧收据（纯文生）不匹配 → 全部重投；其中 4 个卡在带图队列里
   超时，把已经花掉的纯文生成品晾在一边。修法是 `reuse_receipt()` 历史复用 + `ref_image` 开关：
   本轮要哪个版本就先把那版从 `previous_results` 找回来，找不到才生成。

## 7. 生成与服务侧（免费档）

* 模型：`cogvideox-flash`（`model_policy.COGVIDEOX_MODEL`），payload 稳定三字段
  `model/prompt/quality`，幂等可复现；红线 `PROMPT_GUARDRAILS` 单一出处（`model_policy.py`）。
* 速率：免费档实测**每约 60 秒一镜**，单镜 5.1 秒 / 1792×1024 / h264；38 镜一轮约 45 分钟。
  免费档偶发限流（1305），提交侧会自动退避重试（20s→25s→30s…，最多 20 次）。
* 断点续跑：每镜一个 SHA-256 收据（request_hash + 文件 sha256），中断后重投只补缺口；
  瞬时故障（1234 网络错误 / 1305 访问量过大）自动重投新任务，三连败才记 failed。
* 出片：`render.py` 把 1792×1024 的素材放大裁切成 1920×1080，水印位置用 `delogo` 抹掉，
  再叠信息卡、分句字幕、常驻标签与信息卡小字。

## 8. 出片前的逐镜复审（38/38 之后）

38 镜全齐（第 5 轮，`missing=0 failed=0`）后把 `qa/Sxx.jpg` 拼成接触表逐镜过目，发现 5 处要修的：

| 镜头 | 看到的 | 修法 |
|---|---|---|
| S39 | **露脸镜里没有人脸**——俯拍拍到法庭天花与桌椅（判决这镜全靠法官的脸压住） | 提示词改成「waist-up、法官在画面中央、脸清楚地抬起」，并删掉 clerk / defence lawyer（原提示词一边写「no extra people」一边描述另外两个人，自相矛盾） |
| S33 | **镜头内换场**：4 帧室外雪景 + 2 帧室内人物 | 提示词写死「interior only … no window, no outdoor view at any moment」，删掉道具级细节（录音机）压长度 |
| S29 | 要的是「他一个人走过那条走廊」，出来的却是人像近景，走廊没了 | 改成**从背后跟拍**、人小景深的走廊纵深（同时撤掉露脸登记与 `{C1}`：背影镜看不到脸，本来也不该占露脸配额） |
| S43 | 牛棚物证镜里出现躺倒的深色形状，观众会读成遗体 | 改成木托盘上的三件静物（锈镐头 / 绳圈 / 防水布），并写明「no clothing and no figure lies anywhere」 |
| S16 | 2006 年 9 月的旌善山路下着雪 | 写明 late summer、绿叶、无雪（模型把「旌善」直接联想成冬季雪景） |

复审用的接触表拼图脚本没有入库（一次性工具）；判据与 `face_cast.py check-frames` 一致：场景是否对、
有没有换场/畸变/伪文字/多余人物、露脸镜有没有脸。
