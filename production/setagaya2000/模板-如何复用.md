# 世田谷模式 · 新片复用模板

**用途**：从《世田谷一家四口杀人案》起，新片一律按这一套流水线做。本文是"照抄能跑"的清单：
告诉你哪些文件是引擎（原样复制）、哪些是内容（必须重写）、哪些常量必须替换、以及这套流程真实踩过的坑。

**参考实现**：[`production/setagaya2000/`](.)（29 镜 / 180.0 s / 24 fps / 1080P / 语音逐镜锁时间 / QC 全绿）。
更早的 [`production/rabies1885/`](../rabies1885/)（45 镜 × 4 秒网格、7 张信息卡、whisper 逐字听检）与
[`production/gilgo/`](../gilgo/)、[`production/dahlia/`](../dahlia/) 仍可用，但**不再作为默认模板**。

---

## 一、这套模板和狂犬病模式的差别

| 项 | 狂犬病模式（旧默认） | **世田谷模式（本模板）** |
|---|---|---|
| 镜头数 / 节奏 | 45 镜 × 4 秒规划网格 + 7 张信息卡 + 片尾卡 | **29 镜，时长由旁白自然长度决定**（本例 4.48 / 5.184 / 7.328 s 三档），不做信息卡 |
| 旁白与镜头 | 6 章长段旁白，切点再对齐分句 | **一镜一句**：`audio/Sxx.mp3` ↔ `shots[Sxx]` ↔ 字幕一条，三者同起止 |
| 帧率 | 30 fps · 5400 帧 | **24 fps · 4320 帧**（Agnes 2.5 Flash 源片更贴 24） |
| 模型 | Agnes Video（1080p 直出） | **Agnes Video 2.5 Flash，720P 源片 → 后期放大 1080P**，`seconds` 只能取 4/5/6/7/8/9 |
| 校验位置 | 本机 + Actions | **图像/字幕/音频闸门全部在 runner 上跑**（本机常缺 CJK 字体与 ffprobe） |
| 触发器 | GEN / RENDER / VERBATIM / VISUAL_QC 四份 yml | **一份 yml + 三个 marker**：`GEN_REQUEST` / `RENDER_REQUEST` / `QC_REQUEST` |
| 听检 | whisper CER ≤ 0.15 | 无 ASR 环节；字幕时间由 `build_audio.py` 从语音活动窗口直接算出（更准，不需要兜底） |

## 二、目录清单：哪些照抄、哪些重写

`production/setagaya2000/` 共 149 个受版本控制的文件，按角色分三类。

### 1. 引擎（原样复制，只改常量）

| 文件 | 作用 |
|---|---|
| `generate.py` | Agnes 调用 + 全部分支入口：`--validate` / `--clips-only` / `--render-only` / `--payload '{"mode":…}'` |
| `render.py` | 24 fps 合成、ASS 字幕、片尾卡、封面、技术报告；`normalize_clip()` 把源片统一到 1920×1080 |
| `build_audio.py` | 逐镜语音铺时间轴、算字幕窗口、程序合成 BGM 与音效、混音与实测报告 |
| `qc.py` | 成片质检：容器 / 黑帧 / 冻结 / 闪烁 / 字幕 / 音频 / 封面 + `export_fullres_stills()` |
| `throttle.py` | 共享 61 秒闸门（Agnes 队列满时按 61 秒重试） |
| `ffprobe_shim.py` | 没有 ffprobe 的镜像上的替身（PyAV → `ffmpeg -i` 兜底） |
| `workflows/setagaya2000-gen.yml` | 生成 / 出片 / 质检合一的 Actions 工作流（**仓库根同名文件是真正生效的那份**） |

### 2. 内容（必须重写）

| 文件 | 说明 |
|---|---|
| `build_story.py` | **唯一内容源**：29 镜时间轴、逐镜旁白、人物与场景设定、提示词、字幕高亮词、片尾提问、发布文案 |
| `story.json` / `screenplay.md` / `audio/manifest.json` / `镜头提示词与生成记录.md` | 全部由 `build_story.py` / `prompts_report.py` 生成，**不要手改** |
| `reference/01–07*.png` | 角色与场景定稿参考图（风格化形象，不复制真实肖像） |
| `抖音脚本.md` / `抖音发布文案.md` | 发布文案 |
| `README.md` | 本片状态表与交付清单 |

### 3. 运行产物（不入库或按需入库）

`results.json`（断点续跑状态）、`qa/*.jpg` + `qa/*.json`（逐镜截图与探针）、`qa/fullres/`、`qa/sheets/`、
`qa/qc-summary.md`、`run.log`。`work/` 永远不入库（已在 `.gitignore`）。

## 三、开一部新片：九步

```bash
SLUG=ripper1888 ; BRANCH=arena/<本次会话分支> ; NEW=production/$SLUG
cp -a production/setagaya2000 "$NEW"
rm -rf "$NEW/work" "$NEW/qa" "$NEW/audio"/*.mp3 "$NEW/results.json" "$NEW"/*_REQUEST "$NEW/__pycache__"
```

1. **复制目录并清空运行产物**（上一行命令）。`reference/`、`results.json`、`qa/`、`audio/*.mp3` 都要清掉。
2. **全量替换常量**（漏一处就跑不起来，`grep -rn` 自查）：

   | 常量 | 出现位置 |
   |---|---|
   | 分支名 `arena/fed820f6-desktop-tutorial` | `.gitattributes` 无、但 `generate.py::BRANCH`、`.github/workflows/<slug>-gen.yml` 的 `on.push.branches` / `jobs.produce.if` / `checkout.ref` / `env.TARGET_BRANCH` / `concurrency.group` 共 5 处 |
   | 项目 slug `setagaya2000` | 所有 `work/setagaya2000/…` 路径、`RUN_LOG`、工作流文件名 |
   | 片名 | `generate.py::DELIVERY_FILM`、`render.py` 的封面与片尾卡文案、`qc.py::FILM_NAME/COVER_NAME/SRT_NAME` |
   | 关键帧数 | `FPS`、`TOTAL_FRAMES`、`DURATION`（本片 24 / 4320 / 180） |

3. **先写事实边界**：`build_story.py` 顶部的 `SOURCES` / `PRINCIPLES` + `screenplay.md` 的「事实边界」。
   每句旁白都要能指到一条公开来源；未定论的事不写成结论；有更新的官方口径时**以最新官方见解覆盖旧报道**
   （本片就因为 2024-12 警视厅首次公开"浴室窗进出"而把"从玄关离开"的旧说法全部改掉）。
4. **写 29 镜**：`SHOTS` 里每镜 = 号 / 时长档（4–9 s）/ 运镜 / 叙事职责 / 角色 key / 提示词 /
   **该镜旁白一整句**。约束：
   - 一镜一句，字数 ÷ 时长 ≤ 4.2（本片 3.58 字/秒），**不许加速凑时长**；
   - 提示词只写画面与运动，不写可读文字（标题、字幕、数字一律后期加）；
   - 每镜必须写"怎么动"（推、摇、跟、手持、粒子），静态图会被 `validate` 的运镜词表拦下；
   - 不出现遗体、伤口、血腥、作案过程；真实人物只给剪影/背影。
5. **配音**：一镜一条 mp3，低沉男声，`audio/manifest.json` 记 `text / voice_id / sha256 / target_start / target_duration / alignment=shot-locked`。
   `build_story.py` 会把 sha 写进 manifest（文本没变才会复用旧 sha，所以改文案后要重新录音、再跑两遍 `build_story.py`）。
6. **跑本地闸门**：`python3 production/$SLUG/build_story.py` → `generate.py --validate` → `python3 -m unittest production/tests/test_$SLUG.py -q`。
7. **生成素材**：写 `GEN_REQUEST` 为 `{"mode":"clips","workers":2}` 并 push；工作流先跑 S01 金丝雀，通过后全量。
   进度看 `results.json` 的 `phase` 与 `qa/*.json`；坏镜头用 `{"only":"S22"}` 单镜重做。
8. **出片**：写 `RENDER_REQUEST` 为 `{"mode":"render","workers":1}` 并 push。注意 **QC_REQUEST 优先级高于 RENDER_REQUEST**，
   想重渲必须先 `git rm` 掉 `QC_REQUEST`（本片在这上面白等了一整轮）。
9. **质检**：写 `QC_REQUEST` 为 `{"mode":"qc"}` 并 push，runner 上跑 `qc.py` 并把 `qa/fullres/`、`qa/sheets/`、
   `qa/qc-summary.md` 自动提交回分支。硬闸门全过再交付。

## 四、触发器与 payload

| marker 文件 | payload | 行为 |
|---|---|---|
| `GEN_REQUEST` | `{"mode":"clips","workers":2}` / `{"only":"S22"}` | 调 Agnes 2.5 Flash 生成 720P 片段，写 `results.json` + `qa/Sxx.jpg` |
| `RENDER_REQUEST` | `{"mode":"render","workers":1}` | 只做 1080P 出片：拼接 / 字幕 / 混音 / 封面 / 技术报告 / 发布到 `交付/` |
| `QC_REQUEST` | `{"mode":"qc"}` | 只跑 `validate` + `qc.py`，把质检产物提交回分支（**优先级最高**） |
| 无 marker | 默认 `{"only":"S01","workers":2,"canary_then_full":true}` | 金丝雀 → 全量 |

沙箱 token 没有 `actions:write`，`gh workflow run` 会 403，所以**只能靠 marker 文件 push 触发**。

## 五、闸门（任何一道不过都不许交付）

| 闸门 | 在哪 | 拦什么 |
|---|---|---|
| 内容一致性 | `generate.py --validate` | 时间轴不是 180 s、镜数不是 29、提示词为空、旁白与 story.json 不一致、配音 sha 对不上、参考图缺失 |
| payload 形状 | `generate.py` | 2.5 Flash 只收 `model/prompt/seconds/size/aspect_ratio/mode/n/seed` 八个字段，多一个字段直接报错 |
| 源片规格 | `render.py::normalize_clip` | 源片不在 `results.json` 里、sha 不符、时长与镜头时长不符——**绝不用静态图顶替** |
| 成片规格 | `render.py` 收尾 | 不是 1920×1080 / 180.0 s / 4320 帧 / 48 kHz 立体声就直接失败 |
| 混音 | `build_audio.py` | 低于 −30 dBFS、峰值过热、BGM 压旁白不足 18 dB、末秒未淡出至静音 |
| 成片质检 | `qc.py` | 黑帧（切点 ±0.45 s 的淡黑豁免）、冻结 > 2.5 s、闪烁跳变、字幕条数与文本、封面尺寸、末秒静音 |
| 人工签收 | 人 | 逐张看 `qa/fullres/`（原生像素查 AI 伪文字、面部崩坏、字幕遮挡）——机器不替人签收 |

## 六、这套流程真实踩过的坑（照抄时先看这一节）

1. **libass 的 `\pos` 是以文字块中心定位**，不是锚点左上角。按"左上角"算会把右上角常驻标签推出画面；
   实测宽度（本片 535 px）后再算中心：`1324 + 535/2 ≈ 1592`。
2. **切点前后的淡黑不是缺陷**。`qc.py` 原来把 0.3 s 转场淡黑判成黑帧（`[156.0]`），
   现已按镜头切点 ±0.45 s 豁免。
3. **本地没有 ffmpeg / ffprobe / CJK 字体**：本地 dry-run 会出现豆腐块，封面文字缺字。
   图像、字幕、音频的最终 QC **一律在 runner 上跑**，本机只做 dry-run 与结构检查。
4. **`manifest.json` 的 sha 是"文本没变才算"**：改了旁白文案后，`build_story.py` 第一遍会把 sha 写成 `null`，
   要**再跑一遍**才会记录新音频的 sha，然后 `--validate` 才过。
5. **`manifest.json` 的 `voice` 必须等于 `story.json` 的 `narration_spec.voice_id`**，改音色后要两处同步
   （本片曾留下 voice-01 / voice-00 不一致，`build_audio.py` 会直接抛错）。
6. **push 前必须 `git pull --rebase`**：Actions 会持续向同一分支写 checkpoint，直接 push 会被 non-fast-forward 拒。
7. **`git show FETCH_HEAD:<大文件>` 会静默截断**：先 `git show … > /tmp/x` 再读。
8. **`results.json` 的状态会随 Actions 翻转**，读之前先 `git fetch` 再从 `FETCH_HEAD` 取。
9. **单轮 TTS 上限 10 条**：29 条旁白要分 3 批。
10. **沙箱下载 Agnes 成片会 TLS 断连**（`SSLZeroReturnError`）：视觉复核用仓库里的 `qa/*.jpg`，别浪费时间重试。
11. **ASS 颜色是 `&HBBGGRR`**：金色 `#F4C95F` 要写 `&H005FC9F4`，写反会变成浅蓝。
12. **模板内联文案不会跟着 `story.json` 变**：片尾卡、封面、README 摘要都是脚本里写死的字符串，
    改内容后 `grep` 一遍残留（本片曾出现末条字幕与片尾卡重复同一句话）。
13. **优先级陷阱**：`QC_REQUEST` 存在时永远走 QC，`RENDER_REQUEST` 会被忽略（见第三节第 8 步）。
14. **风格差异要写在文档里而不是反复改 STYLE**：本片夜景外景偏写实、室内家族戏偏插画质感 3D，
    已确认这是内容差异不是风格漂移；改 STYLE 会让已生成的镜头全部作废。
