# 制作过程 · 《日本座间九人案：一间公寓里的九条人命》

照 [`新题目开工手册.md`](../../新题目开工手册.md)（狂犬病模式）做的第四部片子，
第三部露脸模式的片子（前两部是《雨夜屠夫林过云》《韩国雨衣杀手柳永哲》）。
本文件记录：每一步对应哪个文件、踩到什么、还剩什么没做完。

分支：`arena/a12ae3fa-desktop-tutorial`　项目：`production/zama2017`　成片目标：180 秒 / 1920×1080 / 30 fps。

---

## 1. 选题与素材来源

- 用户上传的 40 镜文案稿（`文档/20261007-104752_粘贴的文档_20261007-104752.txt`）给出叙事骨架：
  公寓开门 → 失踪 → 真相 → 审判 → 结尾升华。注意上传稿把部分史实说得含糊
  （如「不到 20 平方米」「十几岁到二十多岁」），一律按公开报道改写为精确口径。
- 用户的三条硬要求：**3D 动画视频（不是图片视频）、可以露脸（不同人物不同脸、同一人物同一张脸）、
  人多镜头多一些、剧情丰富饱满**。落实：4 个露脸角色（凶手 / 老刑警 / 年轻女警 / 哥哥），
  8 个露脸镜头（S05 / S06 / S17 / S24 / S27 / S30 / S32 / S35），38 个 Agnes 镜头拉满。
- 事实核查：10 条公开来源（BBC 日文、纽约时报、电讯报、产经新闻、UDN 转角国际、海峡时报、
  4 条转引当时报道的人物/案件梳理），逐句对照写进 [`史实核对.md`](史实核对.md)。
  受害者姓名不在成片与核对文档里出现，只用聚合数字。

## 2. 与上传稿的差异（用户稿 → 成片稿）

| 上传稿 | 成片 | 为什么 |
|---|---|---|
| 40 镜 × 5 秒 | 45 镜 × 4 秒规划网格（38 个 Agnes 镜头 + 7 张信息卡） | 本流水线是三分钟 45 镜 × 4 秒结构；镜头数变了，内容不变 |
| 「不到 20 平方米」 | 「十几平方米」（共同社口径 13.5 平方米，不写小数） | 每句话都要能指到来源 |
| 「十几岁到二十多岁」 | 「十五岁到二十六岁」（确定判决口径） | 同上 |
| 「2020 年法院判决」 | 「二〇二〇年十二月十五日立川支部死刑 → 撤回上诉 → 二〇二一年一月确定 → 二〇二五年六月二十七日执行」 | 判决链条完整，执行是 2025 年的新事实 |
| 未提男性被害经过 | 「其中那名男性，是来找女友的」 | 公开报道确认，且是全片最让人记住的一句 |
| 40 镜全是旁白+画面 | 加哥哥（C4）、年轻女警（C3）两条人物线，N04 整章讲转机 | 用户要求人多、剧情饱满 |

## 3. 内容与闸门

```bash
python3 production/zama2017/build_story.py            # 唯一内容源 → story.json + audio/manifest.json
python3 production/face_cast.py check-prompts --project production/zama2017   # 露脸静态闸门
python3 production/zama2017/generate.py --validate    # 时间轴 / 提示词 / 配音 SHA
```

- 45 镜 = 38 agnes + 7 信息卡（S02 案件名片 / S11 凶手档案 / S18 猎手的手法 /
  S25 转机 / S36 关键日期 / S41 判决 / S43 执行）；每个镜头只用一次，`make_edl` 有断言。
- 解说 6 段 790 字（含标点）；TTS 原始 174.57 s → `tighten_pauses.py` 收紧到 158.11 s（只剪静音），
  可用窗口 168 s，实际变速比 **0.941**。
- `CUTS` 按 `audio/clause-times.json` 的**分句起点 − 0.15 s** 重对，`clause_times.py --check-cuts` 全绿。
- 片头第一行 18 个字按 102 px 无换行会溢出（ASS WrapStyle 2 不换行），按 lamkorwan 的办法拆成两行：
  `日本座间九人案 / 一间公寓里的九条人命 · 二〇一七 座间`。

## 4. 露脸模式（本片重点）

- 四个虚构匿名角色：**C1 年轻男子（凶手）**、**C2 老刑警**、**C3 年轻女警（网络搜查）**、**C4 哥哥**；
  `cast.json` 里每人一条面容 token、一个固定 seed、一张定妆照。
  **不做任何真实人物的肖像还原**——凶手不是白石隆浩本人的脸。
- 同一张脸跨镜稳定靠三件事叠加（沿用 raincoat2004 的接线，`generate.py` 从那部复制后只换项目名，
  diff 确认除项目名/分支名/片名外逐字节一致）：
  1. 提示词里**逐字节**照抄该角色的 face token（`{C1}`…`{C4}` 占位符从 `cast.json` 注入）；
  2. 单角色镜头用**角色 seed**（`shot_seed()`：C1=20170822 入居日 / C2=20171030 搜查日 /
     C3=20171031 逮捕日 / C4=20171024 报警周）；
  3. 四个角色的**首次露脸镜头（S05 / S06 / S24 / S27）用定妆照做图生视频首帧**。
- 双人镜头 S35（C1 与 C2 同框）**只对 C1 锁脸**，老刑警在该镜只给背影（静态闸门拦一镜两 token）。
- 两道闸门：`check-prompts`（生成前，已 PASS）＋ `check-frames`（已接进 `*-visual-qc.yml`，出片后跑）。

## 5. 生成与复审（进行中）

- 38 个 Agnes 镜头，每镜 7 s / 24 fps / 1080p，创建节流 75 s，两个 worker 共享闸门（≈48 分钟排队）。
- 断点续跑：`results.json` 按请求哈希复用；改提示词只重做变了的镜头。
- 复审清单（`qa/` 接触表 + `delivery/face-cast/` 人脸接触表，人眼判决）：
  - [ ] 38 镜逐镜：场景对不对、有没有中途换场、有没有伪文字（**放大到原始像素**，街景/屏幕/证件是重点）
  - [ ] 8 个露脸镜：同一角色跨镜同一张脸，四角色一眼可分
  - [ ] 坏镜头 `{"only":"Sxx"}` 重做
