# 《玛丽·赛勒斯特号》解说卡顿/丢字吞音——v3.2 逐帧排查与修复记录

> v3.1（tag `maryceleste1872-v3.1`）被用户否决：「没解决卡顿,开头不久就开始解说卡卡的」
> 并新增「丢字吞音」「解说词要跟片段等长」。本记录是 v3.2 的样本级取证与修复链终值。
> v3.1 的 25 项排查数值见 git 历史（commit 67cfffd），仅作基线，不再代表交付。

## 一、样本级取证（逐帧定位）

### 1.1 三联声谱对照（raw 原声 / v3.1 分句版 / 成片）
- **v3.1 分句版每条分句接缝处有竖亮线 = 硬拼接爆点**（切片重建 `out[i:i+len]+=piece`
  在词边硬切、零淡接），N01 开头 2.8–4.25s 有 1.45s 黑洞 = 大停顿。
- 爆点 + 大洞 + 均摊停顿 = 用户听到的「卡卡的」。
- TTS 原声（v2/v3 同）在语段接缝处自带 10–50ms 碎块与 30–280ms 微洞（引擎分块拼接行为，
  N02 碎块 t=13.22s/10ms、N01 无）——原声层问题单独处理，不掩盖。

### 1.2 丢字吞音定位
- v3.1 链的 `trim_to_speech`（RMS0.01+5ms 边距）/`shrink_internal`/DP 行界切片都在**词边下刀**：
  软辅音/送气音低于阈值被当静音切掉，行界本身还会漂进词中间（N08「你觉得」行界落在词中）。
- 结论：**任何以行界/能量边为刀口的重建都会吞字**；v3.2 起只允许在真静音核心内剪/插。

## 二、v3.2 修复（pacing.py 重写：连续波形间隙重映射）

1. **零切字**：语音段整段原样搬运，只在 10ms 块 RMS<0.004 的真静音核心里剪/插；
   接缝两侧各留静音余量 + 4ms 淡接。
2. **层级停顿固定目标**（story.json 全文还原标点，不取行尾字）：
   逗 0.22s / 分号 0.28s / 句号 0.55s / 感叹 0.60s（“绳子断了”“都消失了”）/
   疑问 0.75s（“回答是无人知晓”）；N03 i==8 后、N08 i==2 后补重 +0.15s。
3. **句内微洞** ≥100ms 收到 80ms；<100ms 一概不动（辅音尺度，防啃字）。
4. **行界防漂**：间隙核心只认「界域 ±[0.5s,0.8s] 内、未被相邻行界认领、≥45ms 的最长静音段」；
   没有合格静音就保持原样，绝不在词中插停。行时间贴真实语音块（<45ms 微洞并块，
   一行跨多块按字数比例切），语速/字幕/切点全以真实语音为准。
5. **解说词跟片段等长**：紧凑口播 + 短层级停顿交给 render.chapter_layout 的
   atempo（0.78–1.15）慢放铺满窗口——悬疑语感慢语速，字幕/EDL 同步换算。
