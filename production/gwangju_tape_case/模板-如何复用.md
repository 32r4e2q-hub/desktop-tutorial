# 光州胶带案模式 · 新片复用模板

**用途**：第 15 期《光州胶带案》起，用户确认的画面文字层成为今后默认：**画面内解说词字幕 + 画面中间偏下注释**。本文是“照抄能跑”的清单。

**参考实现**：[`production/gwangju_tape_case/`](.)（30 镜 / 180.000s / 24fps / 1920×1080 / 628 字 / 30 条逐镜字幕 / 9 条金色注释 / 无 BGM / verify_master PASS）。

---

## 一、默认画面文字层（必须保留）

共享引擎：`production/gwangju_style.py`。新题目脚手架会自动复制；模板渲染器默认烧录三层。

| 层 | ASS Style | 位置 | 字号/颜色 | 规则 |
|---|---|---:|---|---|
| 解说词字幕 | `Caption` | 底部居中，`MarginV=62` | 44px 白字黑边；关键词金色 50px | 一镜一句/逐句同步，窗口必须落在本镜内 |
| 钩子大字 | `Hook` | 居中偏下，`MarginV=275` | 78px 白字黑边；关键词金色 86px | 每条严格 2 秒，不挡主体 |
| 注释 | `Explainer` | **画面中间偏下**，`MarginV=200` | 32px 金色黑边 | 只补充可核实事实、时间线、术语、法律边界；帮助读者看懂 |
| 片尾标题 | `Title` | 居中偏下 | 104px 金色 | 只在片尾后期添加；AI 源片禁止自绘文字 |

去闪烁默认滤镜：

```text
deflicker=size=61:mode=am,hqdn3d=3:2:9:9,
scale=1920:1080:flags=lanczos,fps=24,
eq=contrast=0.97:brightness=0.018:saturation=0.94
```

不要叠加旧版帧级 gamma/blend“修复”；它曾反而制造亮度尖峰。

## 二、开新片的两条路

### A. 只要默认文字层（最快）

```bash
python3 production/new_topic.py --slug <slug> --title "<片名>" --branch <当前分支>
```

脚手架会复制 `gwangju_style.py`，并在 `build_story.py` 生成 `HOOKS` / `EXPLAINERS` 占位。填完内容后：

```bash
python3 production/<slug>/build_story.py
python3 production/<slug>/generate.py --validate
```

`production/templates/render.py` 会把 `presentation.hooks` / `presentation.explainers` 烧进 ASS。旧狂犬病/世田谷引擎仍可用，但**新片必须保留这三层文字**。

### B. 完整 30 镜 reference 模式（角色/场景/道具一致性要求高）

复制本案目录并清空运行产物：

```bash
SLUG=<slug>; NEW=production/$SLUG
cp -a production/gwangju_tape_case "$NEW"
rm -rf "$NEW/qa" "$NEW/audio/"*.mp3 "$NEW/results.json" "$NEW/GEN_REQUEST" "$NEW/CANCEL_REQUEST" "$NEW/__pycache__"
```

必须替换：

| 常量/文件 | 位置 |
|---|---|
| 分支名 | `build_story.py::BRANCH`、`generate.py::BRANCH`、工作流 `on.push.branches` / `if` / `checkout.ref` / `concurrency.group` |
| slug / work 路径 | 所有 `production/gwangju_tape_case`、`work/gwangju_tape_case` |
| 片名 / 成片名 | `build_story.py::TITLE`、`story.json.film_name`、`qc.py` 默认成片路径、封面文件名 |
| 内容 | `ROWS`、`CHARACTERS`、`CHARACTER_SEEDS`、`HOOKS`、`EXPLAINERS`、`FACT_CHECK.md`、发布文案 |
| 参考图 | `reference/` 全部重做；`approvals.json` 逐张 approved + SHA-256；`revision.txt` 固定不可变 commit |
| SFX | `build_sfx.py::CUES` 按新脚本重写；仍无 BGM |

## 三、顺序（不可提前生成视频）

1. 写 `FACT_CHECK.md`：每句旁白能指到公开来源；未定论只写推测；法律口径限定适用范围。
2. `build_story.py`：30 镜 / 180s；一镜一句；`HOOKS` 每条 2s；`EXPLAINERS` 放在中间偏下。
3. 参考图逐张打开检查，写 `reference/approvals.json`；固定 revision。
4. 本地闸门：

```bash
python3 production/<slug>/build_story.py
python3 production/<slug>/preflight.py
python3 production/<slug>/generate.py --validate --clips-only
```

5. `GEN_REQUEST={"mode":"clips","workers":2}` push；坏镜头 `{"only":"Sxx"}` 单镜重生成。
6. TTS：一镜一条 shot-locked MP3；`build_audio_manifest.py` 写哈希与适配倍数；最大加速 1.55×，不慢放。
7. `GEN_REQUEST={"mode":"render"}` push；两遍编码防音轨截断。
8. 出片后必跑：

```bash
python3 production/verify_master.py \
  --film '交付/<成片>.mp4' \
  --story production/<slug>/story.json \
  --srt '交付/<字幕>.srt'
python3 production/<slug>/qc.py
python3 production/<slug>/narration_fit.py
```

9. 抽帧人眼复核：每 5 镜至少一帧、片尾必看；伪文字/崩脸/闪烁源片重生成，不解释成“不影响”。
10. 系列封面：从**本期最终母版**取帧，裁掉字幕，调用 `production/mystery-cover-template/generate_cover.py`；打开 PNG 复核。
11. 发布文案：标题、简短介绍、提问读者一句话、话题；事实口径与 `FACT_CHECK.md` 一致。
12. 交付：给真实可访问下载方式；写明“技术 QC 与 Agent 抽帧复核通过，仍需用户完整播放人工复核”。

## 五、不要做的事

- 不用其他期截图冒充本期封面。
- 不让 AI 源片自绘中文标题/字幕/注释。
- 不把自动 QC PASS 说成人工签收。
- 不放宽 `verify_master.py` 阈值。
- 不在本地验 `request_hash` 时跳过参考图 SHA-256；验后删除大图，不塞回 Git。
- 不重试已放弃的 GitHub Release 大文件上传路线；本案用 Drive 交付。
