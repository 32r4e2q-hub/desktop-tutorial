# Agnes 免费档候选模型：访问频率与循环续跑

## 授权与边界

用户于2026-10-14要求：通过GitHub已有Agnes API密钥，按免费访问限制编排频率，循环请求直到全部视频生成完成。

- 仅使用 `agnes-video-2.5-flash`，只生成本片story.json的38个动画镜头。
- 720P、16:9，每镜按现有计划请求6秒；三分钟成片为1080p合成，不宣称原生1080p素材。
- 不使用智谱，不轮换密钥绕限额，不换收费模型，不充值。
- Flash是仓库此前记录的免费档候选型号；**尚无本账号零费用账单证据**。队列满、参数校验、甚至生成成功，都不能单独证明计费为零。旧`billing-policy.json`的zero_cost_verified保持false，不伪造已核实状态。
- 新队列由用户的明确循环授权启用。任何余额不足、支付要求、额度错误或鉴权失败均停机。客户端不能强制供应商不扣费。
- GitHub Actions运行时间与Agnes额度是两回事；GitHub-hosted runner会使用Actions分钟额度。使用现有RUNNER_LABEL变量选择自托管runner可避免GitHub-hosted分钟消耗，但必须有实际在线机器。未擅自修改仓库计费设置。

## 请求频率

依据仓库既有免费档约1 RPM的记录进行保守设计；不是声称今天已重新核实官方全部限额。实际平台提示和Retry-After优先。

|场景|策略|
|---|---|
|所有创建POST与状态查询GET|共享全局最小间隔75秒，按响应结束时间计算|
|同时生成任务|最多1个；已有任务先查询，不提交下一镜|
|503且明确video queue is full|120、240、480、900秒退避，之后每900秒再试|
|429限频|150、300、600、900秒退避；Retry-After更长时按更长时间|
|已受理任务查询出现网络错误或5xx|保留同一ID，退避后继续查询，绝不变成新的POST|
|明确支付要求/余额不足/配额错误/401/403|立即暂停，禁止自动换模型和充值|
|参数不合法/模型不可用|暂停检查，不用循环放大同一个错误|
|POST网络中断/未知5xx|可能已经受理，标记submission_ambiguous并暂停人工核对，禁止盲目重发|
|明确任务failed/expired等终态|保留旧ID和响应，15分钟后可重试；同一镜三次明确失败后暂停检查|
|受理任务超过24小时仍未完成|暂停核对；不自动另起一个可能重复的任务|

每次请求之前先保存全局next_request_at、镜头request_hash和提交状态；受理后立刻保存video_id/task_id。轮换Actions runner不重置限流冷却时间。

## 循环与防重

1. `LOOP_REQUEST.json` 启用队列，push到固定分支 `arena/09864331-desktop-tutorial`。
2. 第一次工作流仅跑120秒，目的是实际验证跨工作流接续，而非仅写代码声称会继续。
3. 后续每次 `workflow_dispatch` 运行最多10800秒（3小时），工作流超时上限200分钟，留出归档/接续时间。
4. 到时间但镜头没全部完成时，保存results.json，然后使用Actions自身的GITHUB_TOKEN和actions:write显式调用同一工作流的dispatch API，ref仍为当前固定分支。
5. **不能靠GITHUB_TOKEN的git push触发下一轮**，GitHub通常抑制这类递归触发；workflow_dispatch是明确允许的例外。
6. 同一账号的试片与循环工作流共享并发组kimdaedoo-agnes-api，cancel-in-progress:false，避免相互打断或并发请求。
7. 所有镜头status为completed时停止接续；completed表示下载/技术测量/归档完成，不代表人工画面复审通过，更不代表已交付三分钟成片。
8. 如果GitHub不允许dispatch、Actions额度耗尽、runner离线或归档失败，可能无法持续运行；状态会写明，不能声称后台仍在无限循环。

## 素材持久化

- `results.json`：逐镜来源、任务ID、请求哈希、SHA-256、媒体测量、状态和最近30条响应；持续commit回固定分支。
- 每个生成片段下载后立即以内容哈希命名，上传仓库私有预发布Release `kimdaedoo-agnes-source-clips`。这是素材归档，不是成片发布。
- 视频字节不放入Git提交。Release没有14天artifact保留期，作为CDN之外的持久备份。
- Actions artifact只用于临时诊断，保留14天，不当永久备份。
- `fetch_sources.py`优先从Release恢复并核对SHA，旧记录才使用供应商URL。私有素材用gh/GH_TOKEN访问，不改成公开共享。
- Linear/Notion记交接，Drive已有旁白与制作包备份。它们不执行循环；循环在GitHub Actions运行，不依赖Arena沙箱活着。

## 查看与停止

- GitHub Actions：筛选「金大斗案 · Agnes免费档节流循环」。
- 分支中看 `production/kimdaedoo/results.json` 的completed_count、loop_status、phase、next_request_at和pause_reason。
- 停止：把LOOP_REQUEST.json的enabled改成false并push当前分支；运行中的程序每两分钟读取远端控制，停止新请求。已经受理的供应商任务不会因此在供应商处自动取消，ID保留以便恢复。
- 若Actions整次遭强制取消，正在submitting的镜头会暂停为待核对状态；先查供应商任务，再决定恢复，不删除记录重提。
- 已完成镜头按请求哈希复用，不重新消耗生成请求；改提示词必须先处理已有任务/素材版本。
