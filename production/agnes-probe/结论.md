# Agnes 模型免费可用性探测结论

探测时间：2026-10-12 07:11 – 08:01 UTC
探测方式：GitHub Actions  runner（沙箱出网被限，只有它能连 `apihub.agnes-ai.com` 且持有 `AGNES_API_KEY`）
账号档位：**免费档**（429 报错原文 `the API rate limit for free users`、403 原文 `Insufficient user quota, remaining: $0.000000`）

## 一、结论总表

| 模型 | 类型 | 现在还能免费用吗 | 证据 |
| --- | --- | --- | --- |
| `agnes-video-v2.0` | 视频 | ❌ **已下线** | HTTP 503 `model_not_found`：No available channel for model agnes-video-v2.0 |
| `agnes-video-v2.0-flash` | 视频 | ❌ **已下线/不存在** | HTTP 503 `model_not_found` |
| `agnes-video-2.5` | 视频 | ⚠️ **要钱**（本 key 用不了） | HTTP 403 `insufficient_user_quota`：Insufficient user quota, remaining: $0.000000 |
| `agnes-video-2.5-flash` | 视频 | ✅ **免费可用，但队列满** | 模型名通过校验（400 `prompt is required`）；真提交时 HTTP 503 `video queue is full, please retry later`（6 次重试、跨 8 分钟全满） |
| `agnes-2.0-flash` | 文本 | ❌ **已下线** | HTTP 503 `model_not_found`：No available channel for model agnes-2.0-flash |
| `agnes-2.5-flash` | 文本 | ✅ **免费可用** | HTTP 200，正常返回 `chat.completion`（带 reasoning） |
| `agnes-3.0-flash` | 文本 | ✅ **免费可用（更新）** | HTTP 200，正常回答 "ok" |
| `agnes-3.0-flash-max` | 文本 | ⚠️ **要钱** | HTTP 403 `insufficient_user_quota`：remaining $0.000000 |
| `agnes-2.5-pro` / `-alpha` / `-beta` | 文本 | ⚠️ **要钱** | HTTP 403 `insufficient_user_quota`：remaining $0.000000 |

## 二、`/v1/models` 返回的全部模型（HTTP 200）

```
agnes-2.5-pro-alpha      agnes-video-2.5-flash    agnes-3.0-flash
agnes-image-2.1-flash    agnes-video-2.5          agnes-image-2.0-flash
agnes-2.5-flash          agnes-3.0-flash-max      agnes-2.5-pro
agnes-2.5-pro-beta       agnes-image-2.5-flash
```

注意两点：

1. **这个清单里一个 2.0 都没有** —— 2.0 系列（视频 + 文本）确实已经从平台上摘掉了。
2. **清单不稳定**：同一 key 在 07:11 拿到 11 个、07:14 只拿到 6 个、07:27 又是 11 个。它反映的是"当前有可用通道"的模型，不能当作"我能免费调用"的凭据 —— 真正免费与否只有发请求才知道（2.5-pro 就在清单里，但一调就是余额不足）。

## 三、视频：免费档现在卡在"队列满"

`agnes-video-2.5-flash` 是免费档唯一还能用的视频模型，但真提交生成任务时持续返回：

```
HTTP 503  video queue is full, please retry later
```

这和另外两种失败**性质完全不同**，别混为一谈：

| 报错 | 含义 | 该怎么做 |
| --- | --- | --- |
| `503 model_not_found`（No available channel） | 模型没了 | 换模型，重试没用 |
| `403 insufficient_user_quota`（remaining $0） | 要钱 | 充值或换 flash 档 |
| `503 video queue is full` | 免费队列挤爆 | **可以重试**，但是分钟级退避，不是秒级 |
| `429 rate_limit_exceeded`（for free users） | 触发 RPM 限制 | 免费档视频约 1 RPM，间隔 ≥60s |

免费队列满大概率是 9/25 v2.0 下线后大家都挤到 2.5-flash 造成的，属于平台侧拥堵，需要挑低峰或长时间退避重试。

## 四、2.5 系列的请求参数形状变了

迁移视频代码时不能只改模型名，payload 结构也不一样（上一轮会话实测 + 本次校验均证实）：

```diff
  # Agnes Video v2.0
- {"model":"agnes-video-v2.0","prompt":..., "width":832,"height":448,
-  "num_frames":81,"frame_rate":24}

  # Agnes Video 2.5 / 2.5-flash
+ {"model":"agnes-video-2.5-flash","prompt":..., "seconds":"4","mode":"text",
+  "size":"720P","aspect_ratio":"16:9"}
```

另外 2.5-flash 只支持 **720P**（上一轮会话记录："2.5 Flash 沿用 2.5 的正式参数形状，仅支持 720P"）。

## 五、对本仓库（desktop-tutorial）的直接影响

- 6 个项目（dahlia / dbcooper / gilgo / lamkorwan / rabies1885 / raincoat2004）的 `generate.py` + `render.py` 里硬编码着 `agnes-video-v2.0`，**现在跑一定失败**（`model_not_found`）。
- 迁移目标：`agnes-video-2.5-flash`，同时改 payload 形状和分辨率（480p → 720P）。
- 生成脚本的退避策略要改：现在只处理 429，需要把 **503 `video queue is full` 也当作可重试**，并且退避到分钟级。
- 已生成的 `results.json` 里那些 `.../agnes-video-v2.0/...` 远端 mp4 建议尽快落盘归档。

## 六、怎么复跑这个探针

零成本版（不生成视频，只发空 prompt 触发校验，靠报错判断模型名是否被接受）：

```bash
# 改一行 JSON 再 push 即可触发
printf '{"video_models":"agnes-video-2.5-flash","text_models":"agnes-2.5-flash,agnes-3.0-flash","spend":false,"pause":70,"text_pause":8}\n' \
  > production/AGNES_MODEL_PROBE_REQUEST
git add production/AGNES_MODEL_PROBE_REQUEST && git commit -m "probe" && git push
```

`spend:true` 会真的提交生成任务（消耗额度）。报告由工作流 commit 回本分支：
`production/agnes-probe/report.md` / `report.json`（每次运行覆盖）。

> 注：`gh workflow run` 在当前集成令牌下是 403（Actions 写权限不足），所以只能靠 push 触发。
