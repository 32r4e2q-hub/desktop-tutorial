# 制作过程 · 周克华案：逃亡八年，最后四天

三分钟横版（1920×1080 · 30 fps · 180.0 s · 5400 帧）中文悬疑解说短片。
成片：`交付/周克华案_逃亡八年，最后四天_三分钟_带声音.mp4`
（67,107,053 字节，SHA-256 `7a131df165a5d2bbb4aa609636e7409168ba3d80dff360646e68d3ba663da6d1`，
Release [zhoukehua2012-v1](https://github.com/32r4e2q-hub/desktop-tutorial/releases/tag/zhoukehua2012-v1)）。

## 一、入口：用户上传的 30 镜脚本

用户在会话里把脚本传进 `抖音文案/20261020-000310_粘贴的脚本_20261020-000310.txt`（30 镜 × 6 秒、六幕），
要求「照北九州案的模板做、走智谱免费 key、注意 1301、画面丰富些、多地作案、悬疑低沉男声」。

按手册第 0–2 步把它变成 `production/zhoukehua2012/`：

- 从 `production/kitakyushu2002`（最近一部 CogVideoX 成片）复制引擎与 QC 工具链，
  全部 `kitakyushu2002` → `zhoukehua2012`、出片分支 → `arena/a2b4456e-desktop-tutorial`、片名同步替换；
- **内容全部重写**：`build_story.py` 里的六段解说、45 镜提示词、7 张信息卡、片头片尾卡、
  字幕高亮词、发布文案都是新的；事实按 [`史实核对.md`](史实核对.md) 的 8 条公开来源核对；
- 30 镜 × 6 秒 → 45 镜 × 4 秒规划网格（38 动态 + 7 信息卡），这样每镜 4 秒、六章各约 30 秒，
  抖音的节奏更紧；文案里 30 个镜头的画面点全部保留并扩充成 38 个动态镜头（多地作案、跨省流线、全城搜捕、
  收网、代价）。

## 二、配音（悬疑低沉男声）

- `add_voice` 试听，用户选定 **voice-00**（低沉男声叙述），六段解说用它逐段合成到 `audio/raw/`；
- **TTS 内容审核也拦了两段**（不是视频模型，是配音）：N04「枪击 / 遭遇枪击」、N05「转身开枪 / 还击 /
  缴获两支手枪、三个弹匣、六十二发子弹」被拒。改法：换成同义的事实型措辞
  （「再次响起枪声」「遭到袭击」「两名民警随即上前处置」「随身的物品全部被起获」），
  `story.json`、`manifest.json`、成片字幕三处同步改，重新合成；
- `tighten_pauses.py`：158.76 s → **145.56 s**（只剪静音，不动一个字）；
  `clause_times.py` 对出 74 个分句；`tools/plan_cuts.py` 排骨架后按语义精排，
  `clause_times.py --check-cuts` **45/45 切点差 0.00，全部落在分句停顿窗内**。

> 一次返工：N03 里「苏、湘、渝三地」的顿号让 TTS 在「苏」「湘」之间留了异常长停顿，
> 语速检测报 2.38/2.78 字/秒。改成「苏湘渝三地」重新合成后消失。

## 三、生成：38 镜 CogVideoX-Flash（免费档），1301 的应对

### 3.1 先做内容审核探测，再全量

这部片子的提示词在写的时候就已经按「审核安全」写了一遍（见 3.3），但**没有直接赌全量**：
先只投 10 个最高风险的镜头（人群骚动、绳栏警灯、证物桌、物证封袋、空巷收束、通报会）。

```bash
echo '{"only":"S05,S06,S12,S24,S27,S31,S35,S36,S37,S38"}' > production/zhoukehua2012/COGVIDEOX_GEN_REQUEST
```

结果 10 镜**全部通过**（S05/S06/S12/S24 先出，S27/S31/S35/S36/S37/S38 排队后全出），
于是把 marker 改回 `{}` 跑全量；已出的收据按请求哈希复用，一镜都没重花。

### 3.2 全量首轮：36/38，S01 与 S08 被 1301 拦下

全量一轮约 55 分钟跑完 **36 镜成功、2 镜 1301**：

```
S01  1301  {"code":"1301","message":"系统检测到输入或生成内...（内容审核）"}
S08  1301
```

按引擎的既有设计（`moderation_block()` / `monotonic` 分支），1301 是**单镜**故障：
记 `status=failed` 后跳过这一镜继续跑下一镜，不让一镜把整批掐掉；缺口下一轮按收据补。

本轮还额外跑了一次 `{"only":"S01,S08"}`，**又都被拦**——说明是提示词本身触发了审核，
不是偶发。两镜的写法都是「一张中国地图 / 大区域地图 + 印章 + 案卷」，审核对
「国别地图 + 案件档案 + 盖章」这类组合很敏感。

### 3.3 处理 1301 的三条做法（本片实测有效）

1. **只改被拦的那一镜，不动全片**：`build_story.py` 里改 S01 / S08 两句提示词，
   重跑 `build_story.py` 让请求哈希变化（同时 `results.json` 里旧收据自动归档），再
   `{"only":"S01,S08"}` 只重投这两镜；其余 36 镜的收据一字不动、不再花时间排队。
2. **换构图，不是换形容词**：S01 从「中国地图 + 案卷 + 印章」改成「台灯下一张旧街区地图 + 卷宗 + 眼镜」；
   S08 从「中国地图俯拍 + 指针」改成「一张城市地图俯拍 + 三个红点与红绳」。去掉国别、印章、
   「案卷墙」这类符号后，两镜**一次通过**。
3. **写提示词时就避开高危词**：全片 38 条动态提示词里，`police / gun / pistol / bullet / weapon /
   shoot / blood / corpse / victim / suspect / 城市专名 / 真实姓名` **一个都没出现**（有脚本扫过一遍）。
   要用到就换成环境与物件：民警 → `investigators in plain dark jackets`、枪 → `sealed paper envelopes` /
   `a plastered alley wall with two brief flashes of light`、尸检 → `a laboratory bench`、
   收缴 → `a row of tagged envelopes on a steel table`。这既过审，也正好符合「不展示可模仿细节」的红线。
4. 说明：1301 是**内容审核**，不是额度或故障；重投同样的字是没用的（本片实测两次被拦），
   一定要改提示词改变请求哈希，或带 `{"force":"Sxx"}` 真重抽。

最终：**38/38 生成完成，missing=0 failed=0**，`results.json` 里每镜都有 SHA-256 收据与 `qa/` 接触表。

## 四、复审接触表（人眼）

- 逐张看 `qa/*.jpg`（36 张 + 2 张重做的），重点看：是不是这一镜的场景、有没有换场、
  有没有脸、有没有伪文字；再对成片抽原尺寸帧复核。
- 结论：**没有一张可辨识人脸**（全片人物都是背影 / 剪影 / 远处，符合红线）；
  没有可读伪文字（AI 生成的招牌与纸面都是糊的）；没有血腥、遗体、枪械特写。
- 若干镜头模型「自由发挥」但语义不冲突，接受：
  S13 走廊偏绿、S20 的会议桌几乎空、S31 的证物桌拍得过亮、S38 的通报会是剪影群像、
  S06 没拍出绳栏（用街面人群与民警背影交代）、S36 的交火只剩墙面与灯光——
  都在「AI动画情景重现」的表述范围内，不导致误读。
- 没有需要 `WINDOWS` 收窄的换场尾段（本片每镜取用窗都短，最长 6.6 s，尾段没用上）。

**已知瑕疵（诚实清单）**

- N02 的听检 CER 0.130（本片最高，仍 < 0.15）：`崇/重`、`她/他` 这类同音误听；
  字幕与口播文本逐字一致，人耳听得出是「重庆」，不返工。
- S36（交火）只有墙面闪光与湿地反光，画面信息量偏低但不误导；
  S14 夜市店招是 AI 造的不可读笔画（不是乱码拉丁字母，也不成词）。
- 全片没有真实人物肖像还原，因此**没有**任何一帧能作为「周克华本人」的画面 ——
  这是刻意选择，不是素材缺失。
